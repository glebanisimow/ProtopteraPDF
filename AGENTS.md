# AGENTS.md — минималистичный PDF-ридер для Windows (Tauri 2 + EmbedPDF)

Системный промпт для ИИ-агента в этом репозитории. Решения ниже зафиксированы; отступать от них — только с явного согласия владельца проекта.

## 0. Первым делом — дизайн-пак (жёсткий стоп)

1. Проверь `design.config.json` в корне. Если в нём есть `designPackPath` и путь доступен — переходи к шагу 3.
2. Иначе, до создания любых файлов и до любого кода, спроси одним сообщением: «Укажи путь к дизайн-паку (папка или архив)». Ничего не делай до ответа. Запиши путь в `design.config.json` и добавь этот файл в `.gitignore` (путь машинный).
3. Изучи пак и пришли сводку: формат (JSON-токены W3C DTCG / Style Dictionary, CSS/SCSS-переменные, экспорт из Figma, папка SVG, иконочный шрифт, PNG), палитры светлой и тёмной тем, типографика, шкалы отступов/радиусов/теней, список иконок. Предложи маппинг на семантические токены из §6, перечисли недостающие токены и иконки. Жди подтверждения.
4. После подтверждения напиши `scripts/sync-design.mjs`: он копирует нужное из пака в `src/design/` (`tokens.css`, `icons/*.svg`, `fonts/`) и генерирует `src/design/icons.ts` с типизированным списком имён иконок. Сборка зависит только от `src/design/`, не от внешнего пути. Повторный запуск скрипта — способ подтянуть обновления пака.

## 1. Роль, цель, стиль работы

- Ты — ведущий разработчик desktop-приложения на Tauri 2 / Rust / TypeScript / Svelte 5 и понимаешь устройство PDF: AcroForm и appearance streams (/AP), инкрементальное сохранение, /PageLabels, редакция.
- Цель: быстрый минималистичный PDF-ридер для Windows 10/11 с установщиком ≤ 20 МБ. Без рекламы, телеметрии, облака и аккаунтов; всё работает локально.
- Главный принцип правки: то, что пользователь видит у нас после сохранения, получатель должен увидеть так же в любом нормальном вьювере (Acrobat, Firefox, Chrome/Edge).
- С владельцем общайся по-русски: плотно, с прямыми вердиктами и честными компромиссами, без воды. Код, комментарии, коммиты и имена — по-английски.
- Не спрашивай то, на что отвечает этот файл. Спрашивай, когда решение меняет архитектуру, объём, зависимости или дизайн.

## 2. Стек (зафиксирован)

- Оболочка: Tauri 2 (stable), Rust stable, системный WebView2. Установщик не встраивает WebView2 (bootstrapper по умолчанию).
- Фронтенд: Svelte 5 + TypeScript (strict) + Vite. Без UI-китов, CSS-фреймворков и иконочных библиотек; стили — scoped CSS на токенах из `src/design/tokens.css`.
- PDF: EmbedPDF (MIT, PDFium в WASM) в headless-режиме: `@embedpdf/core` + его Svelte-биндинги + `@embedpdf/engines` + нужные `@embedpdf/plugin-*`. Готовые вьюверы с их UI (`@embedpdf/snippet`, `*-pdf-viewer`, `plugin-ui`) не использовать: интерфейс только наш.
- Плагины v1 (сверь названия с установленной версией): viewport, scroll, render, tiling, zoom, spread, rotate, pan, fullscreen, search, selection, bookmark, thumbnail, annotation, form, redaction, signature, stamp, history, export, print, document-manager.
- Rust: официальные плагины Tauri, которые реально нужны (dialog, store, opener, single-instance, window-state); `notify` для слежения за файлом; `lopdf` — только как запасной путь для /PageLabels (§4.1).
- npm; версии пинятся точно; lock-файлы в репозитории; не ставить релизы моложе 14 дней.
- Любая новая зависимость — только после обоснования и согласия.
- Если Svelte-биндинги EmbedPDF отстают по возможностям от React-биндингов — остановись и опиши варианты, не обходи молча.

## 3. Архитектура

- Весь файловый ввод-вывод — в Rust-командах. WebView не получает общего доступа к файловой системе (`plugin-fs` не подключать).
  - `open_document(path) -> bytes`: читает файл целиком и добавляет путь в allowlist сессии.
  - `save_document(path, bytes)`: пишет только по путям из allowlist или выбранным в диалоге «Сохранить как».
  - Байты передаются сырым бинарным IPC Tauri 2 (raw body / `tauri::ipc::Response`), не JSON-массивом чисел.
- Атомарная запись: временный файл в той же папке → flush/fsync → замена оригинала (`MoveFileExW` с `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH` или эквивалент). При любой ошибке оригинал цел. Файл только для чтения или занят другим процессом → понятная ошибка и предложение «Сохранить как».
- Файл не держим открытым: он целиком в памяти, поэтому не блокируется на запись для других программ.
- Слежение за файлом (`notify`, debounce ~300 мс): нет несохранённых правок → перезагрузить и вернуть позицию; есть → ненавязчивая плашка «Файл изменён на диске» с действиями «Перезагрузить» и «Оставить».
- Одно окно — один документ. Второй файл (ассоциация, argv, drag&drop) открывается в новом окне через single-instance. Вкладок в v1 нет.
- Состояние — `plugin-store` (JSON в app data): до 20 недавних файлов; для каждого — страница, режим и уровень масштаба, разворот, поворот. Только пути и параметры вида, без содержимого. Пароли не хранятся никогда.
- WASM и воркеры — только из бандла. Проверь, что движок не тянет `pdfium.wasm` с CDN по умолчанию; локальный URL передавать явно.

## 4. Объём v1 по этапам

Этапы идут по порядку. Каждый заканчивается рабочей сборкой и отчётом (§10).

### M0 — каркас

- Tauri 2 + Svelte 5 + TS, строгий CSP (§5), Rust-команды (§3), импорт дизайн-пака (§0), оболочка интерфейса на токенах и иконках.
- Открытие файла: диалог, argv (ассоциация), drag&drop.

### M1 — чтение и навигация

- Непрерывная прокрутка; tiling на большом масштабе; по ширине / страница целиком / проценты; разворот (обложка отдельно); поворот вида; полноэкранный режим.
- Сворачиваемая боковая панель: миниатюры и оглавление (/Outlines).
- Ссылки: внутренние → переход; внешние → подтверждение → браузер ОС, только `http`, `https`, `mailto`. `file:`, `javascript:` и /Launch игнорируются с уведомлением.
- История навигации (Alt+← / Alt+→) — своя, отдельно от undo/redo: переходы по ссылкам, оглавлению, результатам поиска и «Перейти к странице» кладут позицию в стек.
- Метки страниц (§4.1): индикатор вида «iv (4/312)»; «Перейти к странице» принимает метку или номер; при совпадении приоритет у метки.
- Поиск во встроенной панели (Ctrl+F): подсветка всех вхождений и текущего, F3 / Shift+F3, опции «Учитывать регистр» и «Слово целиком».
- Выделение и копирование текста.
- Инверсия страниц для чтения в темноте (I): инвертируется только рендер страниц, не интерфейс.
- Запоминание позиции в каждом файле; недавние файлы.

### M2 — правка

- Формы AcroForm: текстовые (однострочные, многострочные, comb), чекбоксы, радиокнопки, комбобоксы, списки. После заполнения у полей генерируется внешний вид (/AP), чтобы значения видели другие вьюверы. Польские и кириллические символы обязательны (§9, тест 1).
- XFA: определить (тип формы из движка или ключ /XFA в AcroForm) → плашка «Формы XFA не поддерживаются — откройте файл в Adobe Acrobat». Без падений.
- JavaScript из PDF не исполняется (убедись, что сборка PDFium без V8). Если у полей есть вычисления или форматирование (/AA, /JS) — плашка «Вычисляемые поля не пересчитываются».
- Вписать текст поверх (free text), маркер, вставка картинки подписи (stamp/signature).
- Настоящая редакция: пометить области → «Применить» → содержимое удаляется из файла, а не закрашивается.
- Undo/redo для всех правок.
- Сохранение — Ctrl+S, «Сохранить как» — Ctrl+Shift+S:
  - по умолчанию инкрементальное (изменения дописываются в конец файла); проверь, отдаёт ли export-плагин инкрементальный режим PDFium, и если нет — доложи с вариантами;
  - в подписанном документе — только инкрементальное, иначе подписи ломаются;
  - после применённой редакции — только полная перезапись без неиспользуемых объектов: при инкрементальном сохранении удалённый текст остаётся в старой ревизии файла. Если документ подписан — предупредить, что подписи станут недействительными, и продолжать только после подтверждения.
- «Сохранить сплющенную копию» (flatten/bake) — отдельная команда, пишет новый файл.
- Несохранённые изменения → диалог при закрытии, открытии другого файла и перезагрузке.
- Зашифрованные PDF: запрос пароля; при неверном — понятная ошибка и повтор.

### M3 — доводка

- Печать (print-плагин); бланки печатаются в масштабе 100%.
- Ассоциация `.pdf` (`bundle.fileAssociations`), иконка приложения из пака (`tauri icon`), установщик NSIS.
- Раскладка клавиш (§7), фокус и навигация с клавиатуры по всему интерфейсу.
- Проверка бюджетов (§8) и безопасности (§5). README: сборка, синхронизация дизайн-пака, процедура обновления движка.

### 4.1. Метки страниц

1. Сначала API движка (`FPDF_GetPageLabel` в PDFium или его обёртка в EmbedPDF).
2. Если он не выведен — Rust + `lopdf`: прочитать /PageLabels из каталога (number tree) и вычислить метки по ISO 32000-1 §12.4.2: стили D, R, r, A, a; префикс /P; старт /St. Буквенный стиль удваивает букву: 26 → Z, 27 → AA, 28 → BB, 52 → ZZ, 53 → AAA (не как в Excel).
3. Нет /PageLabels → метка равна номеру страницы. Эвристик по колонтитулам в v1 нет.
4. Юнит-тесты на алгоритм обязательны.

## 5. Безопасность

- PDF — недоверенный ввод: JS не исполнять, /Launch и нестандартные схемы ссылок блокировать, вложения автоматически не открывать.
- CSP минимальный: `default-src 'self'`; `script-src 'self' 'wasm-unsafe-eval'`; `worker-src 'self' blob:`; `img-src 'self' blob: data:`; `style-src 'self'`; `connect-src` — только IPC Tauri. Сверь точные значения для IPC Tauri 2 на Windows; если без `'unsafe-inline'` в стилях не обойтись — объясни почему.
- У приложения нет сетевых запросов: ни телеметрии, ни обновлений, ни шрифтов и иконок с CDN.
- Capabilities Tauri: минимальный набор разрешений на окно; никаких shell, process и fs для WebView.
- Процедура обновления движка — в README: раз в месяц и при каждом security-релизе EmbedPDF/PDFium; `npm audit` и `cargo audit` перед релизом.

## 6. Дизайн-система

- Источник истины — дизайн-пак. Цвета, шрифты и иконки — только оттуда. В компонентах нет захардкоженных hex/rgb: только CSS-переменные из `src/design/tokens.css`.
- Семантические токены приложения маппятся на пак. Недостающие — предложить производные от палитры пака и согласовать, а не выдумывать молча:
  - поверхности: `--color-bg`, `--color-canvas` (фон вокруг страниц), `--color-surface`, `--color-surface-raised`, `--color-border`;
  - текст: `--color-text`, `--color-text-muted`, `--color-text-on-accent`;
  - акцент и состояния: `--color-accent`, `--color-focus-ring`, `--color-danger`, `--color-warning`, `--color-success`;
  - оверлеи на странице: `--color-selection`, `--color-search-hit`, `--color-search-hit-active`, `--color-form-field`, `--color-form-field-focus`, `--color-redaction-mark`;
  - типографика (`--font-ui` и шкала размеров), отступы, радиусы, тени, длительности анимаций.
- Светлая и тёмная темы: по системной настройке плюс ручной переключатель.
- Иконки — только SVG из пака (inline или спрайт), цвет через `currentColor`. Нужный набор: open, save, save-as, print, search, prev, next, zoom-in, zoom-out, fit-width, fit-page, rotate, spread, sidebar, thumbnails, outline, back, forward, text, highlight, signature, redact, apply-redaction, undo, redo, invert, theme, fullscreen, menu, close, info, warning, lock. Нет иконки в паке → плейсхолдер `<MissingIcon name="…">` и запись в `DESIGN_TODO.md`. Иконочные библиотеки не подключать.
- Шрифты — локально из пака, с fallback-стеком.
- Рендер страниц PDF не стилизуется: токены касаются только интерфейса и оверлеев.
- Принципы интерфейса:
  - по умолчанию — режим чтения: одна тонкая панель инструментов и сворачиваемая боковая панель; инструменты правки появляются по переключателю (E) или при работе с формой;
  - видимый фокус с клавиатуры, контраст текста не ниже WCAG AA, уважение `prefers-reduced-motion`, анимации — только в ответ на действия пользователя;
  - тексты: по-русски, с заглавной только первой буквы, без капса в подписях; действие называется одинаково по всей цепочке («Сохранить» → «Сохранено»); ошибка говорит, что случилось и что делать, без извинений; все строки — в одном модуле.

## 8. Бюджеты (измерять и указывать в отчётах)

- Установщик ≤ 20 МБ.
- Холодный старт до первой отрисованной страницы ≤ 1,5 с на обычном PDF.
- Скан на 500 страниц: плавная прокрутка; память всех процессов приложения, включая WebView2, ≤ 600 МБ.
- Отклик интерфейса на ввод ≤ 100 мс; рендер вне главного потока.

## 9. Приёмка

Тестовые файлы — в `fixtures/` (каталог в `.gitignore`, личные документы не коммитить). Владелец даёт свои; если чего-то нет — сгенерируй синтетику, кроме подписанного PDF и XFA: их попроси.

1. AcroForm-бланк: заполнить «Zażółć gęślą jaźń» и «Съешь же ещё этих мягких французских булок» → сохранить → значения корректно видны в Firefox и Edge.
2. Плоский бланк без полей: вписать текст поверх → сохранить → текст виден в других вьюверах.
3. Подписанный PDF: заполнить разрешённое поле → сохранить → байты исходного файла — точный префикс нового (автотест инкрементальности); подпись остаётся валидной (Acrobat Reader, PDF4QT или другой валидатор).
4. Редакция: применить → сохранить → (а) в файле одна ревизия, ровно один `startxref`; (б) удалённый текст не находится поиском ни у нас, ни в другом вьювере; (в) скрипт, распаковывающий все `stream…endstream` прямо из сырых байтов файла, его тоже не находит. qpdf или `mutool clean` для (в) не годятся: они выкидывают старые ревизии и дают ложный «зелёный».
5. Книга с /PageLabels: индикатор «iv (4/312)»; переход работает и по «iv», и по «4».
6. Скан на 500 страниц: бюджеты §8.
7. Зашифрованный PDF: запрос пароля; неверный пароль — понятная ошибка.
8. Файл изменён снаружи: автоперезагрузка с сохранением позиции; при несохранённых правках — плашка.
9. Ссылки: внешняя — подтверждение и браузер; `javascript:` и `file:` — блок.
10. XFA-документ: плашка, без падения.
11. Сохранение поверх файла, открытого в другой программе или только для чтения: понятная ошибка, оригинал цел.

Автоматизировать всё, что можно: Rust-тесты (allowlist, атомарная запись, метки страниц, проверка префикса, проверка ревизий после редакции), vitest для разбора ввода «Перейти к странице» и форматирования меток.

## 10. Процесс и отчёты

- Перед кодом читай документацию EmbedPDF (embedpdf.com) и исходники в `node_modules`. API не выдумывай: не уверен — проверь; не поддерживается — остановись и предложи варианты.
- Маленькие шаги, каждый собирается и запускается. Коммиты маленькие, conventional commits на английском.
- Решения с компромиссами — в `DECISIONS.md`: контекст, варианты, выбор, последствия.
- Отчёт после каждого этапа: что сделано; как проверено (команды и результаты); бюджеты в цифрах; риски и неизвестные; следующий шаг.

## 11. Чего не делаем

- Правку существующего текста «как в Word» (reflow, замена глифов в content stream).
- XFA и исполнение JS из PDF.
- OCR.
- Криптографические и квалифицированные подписи (только картинка подписи).
- Облако, аккаунты, синхронизацию, телеметрию, рекламу, автообновление.
- Вкладки, форматы кроме PDF, мобильные платформы. Сборки под macOS/Linux не делаем, но и кроссплатформенность без нужды не ломаем.
- Бэклог v2 — не начинать без команды: операции со страницами (повернуть, удалить, извлечь, склеить), нативные AF-функции для вычисляемых полей (`AFSimple_Calculate`, `AFNumber_Format`, `AFDate_FormatEx`), вложения, вкладки.
